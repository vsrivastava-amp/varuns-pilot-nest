# INFRA Task draft
# Suggested title: Add a Bedrock Mantle PrivateLink endpoint to dev EKS

We run `online-pciv-service` for AI-1538 in dev EKS ric1. The service calls OpenAI GPT-5.6 Luna through `bedrock-mantle.us-east-1.api.aws`, but the current EKS path resolves that hostname to public IP addresses.

Please add an Amazon Bedrock Mantle interface VPC endpoint for dev EKS:

* AWS account: `564079877134`
* Cluster: `eks-dev-use1-01`
* VPC: `vpc-0317d6910f3add39a`
* Endpoint service: `com.amazonaws.us-east-1.bedrock-mantle`
* Enable Private DNS for `bedrock-mantle.us-east-1.api.aws`.
* Add endpoint ENIs in the available workload AZs. The cluster subnets that match Mantle's advertised availability are `subnet-0a3cb949a8af631d2` in `us-east-1a` and `subnet-05f1dc5d674c61d34` in `us-east-1b`. Mantle does not currently advertise `us-east-1c` for this endpoint service.
* Allow HTTPS from the EKS workload path to the endpoint ENIs.
* Allow `bedrock-mantle:CallWithBearerToken` and `bedrock-mantle:CreateInference` in the endpoint policy. The workload role already has these IAM permissions through INFRA-3474.

The VPC DHCP configuration uses company DNS servers `10.11.128.70` and `10.11.128.50`. Please make sure requests from EKS resolve `bedrock-mantle.us-east-1.api.aws` to the endpoint's private IP addresses. Enabling the endpoint's Private DNS setting alone may not affect these custom resolvers without the appropriate forwarding rule.

Acceptance criteria:

* The interface endpoint is available with Private DNS enabled.
* DNS from an EKS workload resolves `bedrock-mantle.us-east-1.api.aws` to private endpoint addresses rather than public addresses.
* `online-pciv-service` can run its existing Luna Mantle evaluation successfully without an application configuration change.

This is dev-only. We will measure the dev path before requesting separate endpoints for stage and prod.
